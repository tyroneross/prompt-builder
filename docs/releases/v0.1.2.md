# v0.1.2 — First GitHub Packages release

Pilot of the per-plugin publish flow captured in the
[`publish-packages` skill](https://github.com/tyroneross/RossLabs-AI-Toolkit/blob/main/skills/publish-packages/SKILL.md).

## What's new

- **Published as `@tyroneross/prompt-builder` on GitHub Packages.** Consumers can
  now install the plugin with `npm install @tyroneross/prompt-builder` after
  configuring the scoped registry (`@tyroneross:registry=https://npm.pkg.github.com`).
- **Multi-host parity** — both `.claude-plugin/plugin.json` and
  `.codex-plugin/plugin.json` are now versioned in lockstep (`0.1.2`). A CI
  drift check in `publish-npm.yml` enforces this on every release.
- **CI smoke-test** — `verify-install.yml` chains after every publish and
  sandbox-installs the package using the workflow's auto-provisioned
  `GITHUB_TOKEN`. Catches regressions like empty tarballs, missing manifests,
  or `files:` whitelist drift.

## What ships in the tarball

Per `package.json` `files:` whitelist:

- `.claude-plugin/` — Claude Code plugin manifest
- `.codex-plugin/` — Codex plugin manifest
- `commands/` — slash commands
- `skills/` — skill definitions
- `scripts/` — runtime scripts the skills/commands invoke
- `evals/` — eval harness inputs
- `CLAUDE.md`, `README.md`, `LICENSE`

Excluded from the tarball: anything not on the whitelist (`.git`, dev
artifacts, etc.).

## Install for consumers

```bash
# One-time: add the scoped registry
echo "@tyroneross:registry=https://npm.pkg.github.com" >> ~/.npmrc

# Auth — needs a PAT with read:packages
echo "//npm.pkg.github.com/:_authToken=<PAT>" >> ~/.npmrc

# Install
npm install @tyroneross/prompt-builder
```

The Claude Code marketplace install path (`/plugin` UI) remains unchanged and
does not require any npm/PAT setup. The npm distribution is an alternative
path for tools and pipelines that want to pin the plugin to a specific version.

## Notes

- No code changes vs. the previous `0.1.2` plugin manifest — this is purely
  the packaging + CI infrastructure to make the plugin npm-installable.
- The publish workflow guards against tag-vs-manifest drift and against
  inter-manifest drift (package.json / .claude-plugin / .codex-plugin all
  must agree).

## Invariant compliance

CLAUDE.md invariant 5 ("Zero runtime dependencies — do not add `package.json`
with deps") is preserved. This release adds a `package.json` that contains
**no `dependencies` block** — only publishing metadata (`name`, `version`,
`files`, `publishConfig`, etc.). The plugin remains pure Markdown + JSON +
Node stdlib at runtime. If a future contributor needs to add runtime deps,
that's a separate decision that requires revisiting the invariant.
